# Task qa-001 — Deterministic traceable public Q&A

Read `AGENTS.md`, `PRODUCT_REQUIREMENTS.md`, the catalog model/loader/router,
and `docs/EVIDENCE.md` first.

Implement a bounded deterministic question interpreter over approved active
public catalog records only. Initial intents are: list one offering's benefits,
find offerings for a benefit type, inspect one benefit, and compare two
offerings. Resolve canonical slugs and aliases; return ambiguity rather than
guessing. Every factual statement carries catalog record IDs and exact public
evidence URLs, dates, confidence, and freshness. Unknown, unsupported, stale,
or unapproved facts never become an answer.

The query is ephemeral, length-bounded, and not logged or persisted. The core
must work without an LLM. No vault/card-instance data, source fetch, private
prompt, financial advice, or external action is in scope. Tests use only the
synthetic catalog and cover injection-like text, ambiguity, no-result, stale
evidence, comparison, ordering, citations, and output bounds.
